# Task4｜Harness 工具调用智能体框架搭建
## 任务目标
搭建Pi-Agent风格的Harness调度框架，实现大模型自主判断什么时候调用外部工具（YOLO视觉检测），实现大模型+工具联动。
- 大模型负责理解用户指令、决策是否调用工具
- 工具模块（YOLO）负责摄像头图像识别
- harness作为调度中间层，完成指令分发、结果回传给大模型

## 开发进度
1. 基于LM Studio本地大模型API，搭建基础对话循环。
2. 封装YOLO检测函数，做成可被大模型调用的工具。
3. 编写工具判断逻辑：大模型输出特定指令时，触发摄像头检测。
4. 调试上下文传递：YOLO识别结果传回给大模型，结合画面信息回答用户问题。
5. 整合异常捕获，处理摄像头打开失败、API断开等情况。

## 遇到的问题 & 解决方案
1. 大模型不会主动触发调用YOLO工具
原因：提示词描述不够清晰，模型不知道可用工具。
解决：在系统prompt里写明可用工具、触发关键词，引导模型在需要视觉信息时调用YOLO。

2. 工具返回结果格式混乱，大模型难以读取
原因：YOLO返回原始检测框信息太多，冗余信息干扰大模型。
解决：过滤坐标，只提取物体类别和置信度文本，精简返回内容。

3. 多轮对话上下文不断膨胀，响应变慢
解决：设置上下文窗口上限，丢弃久远对话记录。

## 思考总结
Harness是整个项目的调度核心，相当于智能体的“大脑调度层”。它把大语言模型和外部能力（视觉）连接起来。本地部署的模型受提示词能力限制，工具调用稳定性不如云端大模型，但可以在单机完全离线运行。
